# Guía de evaluación

Esta guía sirve para revisar el progreso sin exigir una solución concreta.

## Escala por ejercicio

- **0 — No iniciado:** no existe una implementación funcional.
- **1 — Inicial:** resuelve parcialmente el problema, con errores importantes o dependencia continua de ayuda.
- **2 — Correcto:** cumple los requisitos principales y el alumno entiende lo que ha hecho.
- **3 — Sólido:** además de funcionar, la solución es clara, accesible, mantenible y contempla casos límite razonables.

## Preguntas útiles durante la revisión

En lugar de preguntar únicamente “¿funciona?”, pide al alumno que explique:

- por qué eligió una etiqueta HTML y no otra;
- qué ocurriría sin una determinada regla CSS;
- cómo cambia el layout a distintos anchos;
- qué diferencia hay entre modificar un array y devolver uno nuevo;
- qué devuelve una función en cada rama;
- qué sucede si una petición HTTP falla;
- qué pasa si el usuario hace dos búsquedas muy rápido;
- cómo distinguiría un problema de datos de uno de presentación.

## Señales de dominio real

Una práctica está realmente aprendida cuando el alumno puede introducir un pequeño cambio sin rehacer todo. Por ejemplo: añadir otro campo al formulario, cambiar el layout de 3 a 4 columnas, alterar una regla de descuento, o añadir un estado de error a una petición.
